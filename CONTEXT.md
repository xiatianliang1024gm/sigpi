# Context

Domain glossary for SigPi. Use these names when discussing seams and
deepening opportunities so future architecture reviews share one vocabulary.

> ADR / spec numbers (e.g. "ADR 0021", "spec-0020") are traceability
> back-references to historical design decisions. Since **ADR 0026** (compaction
> refactor), significant design decisions are written to numbered files under
> `docs/adr/` (the first standalone ADR file is `docs/adr/0026-compaction-refactor.md`);
> older numbers have no files behind them and their decision content lives in
> these entries and in the code comments.

## Domain terms

- **Conversation context** — `src/agent/context.ts` (`ConversationContext`). Owns the summary, recent messages, entry stream; the source of truth for working context.
- **Context budget** — the token budget that drives compaction, defined **per model**. Three model-level fields: `hard_context_limit` (the model's physical total token ceiling, default `200_000`), `reserveTokens` (headroom kept free so the next request fits; the soft limit is derived as `hard_context_limit - reserveTokens`), and `keepRecentTokens` (how much of the recent tail stays verbatim). `ConversationContext` reads the budget from a getter bound to the *active* model, so `/model switch` updates the compaction trigger. Retired term: `contextWindow` (agent-level) — replaced by `hard_context_limit`.
- **Compaction** — the single context-compression path (ADR 0026): older recent messages are summarized into the summary when the token budget is exceeded (auto trigger) or on demand (`/compact`, force trigger). Built from two pure interfaces — **decide** (pure: messages + budget + `systemPrompt`/`toolSchemas`/`pendingUserInput` + `force` → `{shouldCompact, splitIndex}`; the over-limit check runs against the full request shape, `lastUsage`-first estimation) and **execute** (pure: summarizes a message slice via `microCompactMessages` + the model, returns `{summary, usage}`) — orchestrated by a thin `ConversationContext.compact()` (apply). A post-compaction overflow throws `CompactionFailedError` (`reason: "insufficient_compaction"`); there is **no silent trimming** — `trimToHardLimit` is gone. The runner only triggers (pre-request `decide`, `/compact`, or the provider's `context_length_exceeded` → compact → retry once). The in-turn checkpoint (`maybeCompactWorkingMessages`, `TURN_CHECKPOINT_*`) is a **retired term** — there is exactly one compaction path with two triggers. Retired: turn checkpoint, Compactor class, CompactorDeps.
- **Empty-response recovery** — a model response with no text and no tool calls is not a valid final answer (`src/agent/runner.ts`). The runner treats it as a degenerate provider response instead of ending the turn with `No response generated.`: the empty response is **never persisted** (D5 exception), the runner re-prompts the model, bounded at `EMPTY_RESPONSE_MAX_RETRIES`. Under message-level persistence (ADR 0026) there is no longer a "compact-then-continue vs re-prompt" fork — both are "rebuild the request from the context and continue".
- **Tool** — a capability the agent can call, defined by `ToolDefinition` and dispatched through `ToolRegistry`. Built-ins live in `src/tools/builtin/`.
- **Session** — a persisted conversation (`src/session/store.ts`). Stores the entry stream (message + compaction entries), turn history, and a recovery snapshot.
- **EntryStreamSerializer** — `src/session/format.ts`. The single module that converts between a context state (`{summary, recentMessages}`) and the entry stream in both directions: `buildEntriesFromContextState` (state → entries, from scratch), `resolveEntriesForPersist` (state → entries, append-only merge into an existing transcript), and `deriveContextStateFromEntries` (entries → state). Context and store both delegate here, so entry derivation lives in one place.
- **Skill** — an instruction document discovered from skill roots and surfaced to the system prompt (`src/skills/`). Discovery implies trust: a discovered skill is loaded and trusted with no separate gate. "Trusted skill" / "untrusted skill" / "force-load" are retired terms — under load-implies-trust there is no untrusted-discovered skill; pointing `read` at a `SKILL.md` path is just reading a file.
- **Skill root** — a skill discovery directory (`.sigpi/skills` / `.agents/skills`, project or global; enumerated by `collectSkillRoots`, `src/skills/catalog.ts:69`). **Read-only invariant removed (ADR 0023):** SigPi no longer blocks writes into skill roots — the guard was bypassable without a sandbox (e.g. `npx`, subshells, `curl | sh`) and gave false safety. Global skill roots are user-installed and never gated. _Avoid_: trusted roots, allowed roots — the `allowedRoots` read/write allow-list (ADR 0016) was also removed by ADR 0022.
- **Model provider** — the `ModelProvider` seam, defined and constructed in `src/model/provider.ts` (the model module's entry point), that turns a request into a model response. Consumers obtain one via `createModelProvider(config, logger)` and never name the concrete class; `OpenAICompatibleProvider` composes the **OpenAI SDK** (fetch + SSE + retry + timeout for the openai-compatible path) with a slimmed `WireFormatAdapter` (chat-completions or responses) that translates `ModelRequest` ↔ SDK params and SDK chunks ↔ `ModelDelta`/`ModelResponse`, selecting the adapter by `config.apiFormat`. A future non-openai schema (e.g. Anthropic) is a *separate* adapter over a different SDK client, behind the same `ModelProvider` seam — not an extension of this one.
- **Model transport** — the HTTP/SSE/retry/timeout substrate for the openai-compatible path, **delegated to the OpenAI SDK** (`new OpenAI({ apiKey, baseURL, fetch: getProxyStatus().fetchImpl, maxRetries: 0 })`). The SDK owns fetch, SSE framing, and per-call body reading; SigPi owns the **timeout semantics** (a `total request timeout` + the kept `idle/stall timeout`, both merged into the abort signal passed to `client.chat.completions.create`) and the **error classification** (`ModelRequestError` + `RequestFailureKind`, mapped from SDK error types; `truncated` stays SigPi-side via the adapter's `finish_reason` detection). SigPi's own retry/backoff loop wraps the SDK call, so `isRetryableRequestError` + jitter are unchanged. The `WireFormatAdapter` keeps delta-shape knowledge out of the transport, so the transport stays format-agnostic.
- **Idle/stall timeout (静默超时)** — a model request's timeout is measured as *silence*, not total duration: one timer starts at request issue and resets on every received SSE frame (or body chunk), firing only after `timeoutMs` with no bytes. It therefore guards both a dead server (never sends a first frame) and a mid-stream stall, while not killing responses that stream steadily but run long in total. _Avoid_: hard turn deadline. Its companion **`total request timeout`** now closes the gap the old idle-only design left open (see below).
- **Total request timeout (总请求超时)** — bounds the *entire* request from `fetch` to stream end, owned by the OpenAI SDK's `timeout: timeoutMs` (a deadline that does **not** reset on received bytes). It catches the case the idle/stall timer cannot: a model that streams thinking indefinitely but never emits content (reasoning-forever), because reasoning bytes keep resetting the idle timer. Both timers use `timeoutMs` and merge into one abort signal. **Supersedes the deferred `reasoning_timeout`** — the total timeout achieves the same guard without a separate reasoning-phase timer and without changing the idle reset rule (ADR 0005's "no second timer" rejection is likewise superseded). _Avoid_: reasoning_timeout (the deferred per-phase timer is no longer needed), hard turn deadline.
- **max_tokens clamp (max_tokens 裁剪)** — before each request, SigPi clamps the output cap to `min(req.maxTokens, contextWindow − estimatedInputTokens − 4096)` (the `4096` margin is hardcoded, Pi-style; `reserveTokens` is *not* used here — it stays the compaction headroom per ADR 0021). This prevents the oversized-generation truncation (`finish_reason: "length"`) that an unclamped `max_tokens` (e.g. `100000`) produces when a model tries to fill the whole context. `truncated` is still detected SigPi-side via the adapter's `finish_reason`.
- **Reasoning token (思考 token)** — model output that is not the final answer but the model's chain-of-thought, carried in a separate delta field (`reasoning_content` / `reasoning`) rather than `content`. The chat-completions adapter historically ignored it; the streaming-render work captures it so the thinking phase is visible. Under ADR 0025 (A1 render layer) the reasoning is rendered **inside the streaming assistant message's thinking block** (Pi-style), not a separate `ReasoningStreamComponent`, so it is visible during streaming instead of a blank `thinking` label. Distinct from **content token** (the answer text in `content`).
- **Streaming render (流式渲染)** — displaying model output incrementally as SSE frames arrive, rather than buffering until `[DONE]`. The `onDelta` chain is **implemented**: `generate` → `performRequest`/`create` → adapter `onDelta(frame)` (fold into running state + emit a `ModelDelta`) → runner → `TurnProgressEvent` (`model_delta` carrying `{reasoningDelta, contentDelta, toolCallDelta}`). Rendering is display-only — it does not alter the agent turn control flow (still `await` full response before tool calls / compaction). **Event division**: `model_delta` is *render-only*; the phase events (`assistant_message`, `tool_calls_received`, `tool_execution_*`) remain *persistence/logging-only* and are untouched. Tool-call events fire only after `generate()` returns the full `ModelResponse`, so they never overlap with in-flight `model_delta` frames. **Non-TTY / one-shot modes**: `model_delta` is silently dropped in `console.log`-based renderers (compact/clear/quiet); the final answer still prints whole via `assistant_message`. Exception: on a *failed/truncated* turn, the reasoning accumulated so far is printed as diagnostic output, because in the `finish_reason: "length"` case the user most needs to see what the model was thinking. (The pre-A1 "UI shape" / "live-preview lifecycle" clauses about a standalone `ReasoningStreamComponent` are superseded by the A1 render layer — see the next entry.)
- **Streaming render — A1 update**: the A1 render layer (fully Pi-tui, persistent `TUI`) renders the whole turn output (reasoning + content) as Pi-tui components; reasoning renders **inside the streaming assistant message's thinking block** (Pi-style) and content renders live into the same message component, so the standalone `ReasoningStreamComponent` is retired and the deferred "content streaming to UI" item is closed. The event-division, render-only `model_delta`, and non-TTY-drop decisions from ADR 0020 still hold; the "UI shape" / "live-preview lifecycle" clauses above describe the pre-A1 design and are superseded for the TUI path.
- **Interrupt vs retry (中断 vs 重试)** — a user interrupt (ESC → `interruptController.requestInterrupt()` → aborted `AbortSignal`) must be treated as a terminal cancellation, **never** as a retryable network error. **Bug fixed by ADR 0020**: undici's `fetch` surfaces an abort as its own `AbortError` DOMException and does *not* re-throw `signal.reason` (`TurnInterruptedError`), so the transport's catch must detect `AbortError` + `request.abortSignal?.aborted` and throw the interrupt error directly — not classify it as `aborted`/`network_error` and let `isRetryableRequestError` retry it. Before the fix, ESC aborted the in-flight request, the retry loop re-issued it, and the turn re-entered `thinking`, making ESC appear to "do nothing".
- **Wire format adapter** — `src/model/wire-format.ts` (`WireFormatAdapter`) with two implementations: `ChatCompletionsAdapter` and `ResponsesAdapter`. In the SDK era it no longer builds the wire request (`buildUrl` / `toRequestBody` are gone — the OpenAI SDK owns the request); instead it owns **schema translation**: `toParams(request)` maps a SigPi `ModelRequest` (messages, tools, temperature, clamped `max_tokens`, stream flag) into SDK call params, and the **streaming delta mappers** `accumulate(frame)` / `onDelta(frame)` / `finalize()` fold one SDK chunk into running state and emit the complete `ModelResponse` (including `finish_reason`, so `truncated` is detected SigPi-side). Keeping delta-shape knowledge in the adapter is what lets the transport stay format-agnostic and lets a future non-openai schema (Anthropic) drop in as one more adapter over a different client.
- **Agent turn** — one `runTurn()` pass in `src/agent/runner.ts`: user input → some number of tool-call steps → final answer. This is the concrete shape of the "agent loop" in this project; step count is bounded by `maxSteps`. Exceeding the bound ends the turn with a **local** fallback answer built from in-memory `toolExecutions` + `currentGoal` (enhanced `buildMaxStepsFallbackAnswer`) — **no final `tools: []` synthesis call** (that call leaked `<tool_call>` markup and added 500 risk; removed per ADR 0018). The fallback is user-facing only: it states the limit was reached, the task is incomplete, and prompts `go on` to continue.
- **Max-steps fallback** — the local answer emitted when `step > maxSteps`. Assembled from real `toolExecutions` (files read, commands run, calls made) + `currentGoal`; never from a model call. Distinct from **compaction** (a summary of older messages) and from **tool error** (surfaced into a completed turn, `ok: true`, not a fallback).
- **Function calling** — the mechanism by which the model emits `toolCalls` in its response, the runner dispatches them via `ToolRegistry`, and the results are fed back into the working context. Distinct from **Tool** (the capability definition): a Tool is "what can be done"; function calling is "how the model drives it".
- **Context management** — see **Compaction**; this project keeps the working context within the token budget using "summary + recent messages" (ADR 0026: the in-turn checkpoint is retired, persistence is message-level, the runner holds no working-message mirror), corresponding to one of the three teaching concepts claimed by the README.
- **Glyph vocabulary (符号体系)** — the set of prefix characters that define the visual hierarchy for agent progress messages in the TUI. `❯` user input (cyan, 0 indent), `●` model narrative as a new prefix on `AssistantMessageComponent` (0 indent), `⎿` tool-call line (2-space indent). The glyph set is a rendering-layer convention and never appears in model output; it replaces the flat `ToolResultMessageComponent` blocks with an indented narrative stream.
- **Tool line (tool-call 行)** — a two-phase TUI component (`ToolLineComponent`) in the activity log, created via `ReplView.beginToolLine(id, label)` and resolved via `ToolLineHandle`. Phase 1 (started) shows the tool summary label prefixed with `⎿`; phase 2 (finished/failed) appends the outcome inline — a success summary or a red error summary. Replaces the retired `ToolResultMessageComponent` block. _Avoid_: tool-result component, tool-result block.
- **ToolLineHandle** — the handle returned by `ReplView.beginToolLine(id, label)` with two methods: `finish()` marks the tool line succeeded, and `fail(error)` appends a red error summary. The REPL loop (`applyTurnProgress`) holds a `Map<string, ToolLineHandle>` and calls finish/fail on `tool_execution_finished`. Replaces the old `addToolResult` one-shot method on `ReplView`.
